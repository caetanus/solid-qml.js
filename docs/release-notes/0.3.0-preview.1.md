# solid-qml 0.3.0-preview.1

Release date: 2026-10-11 (release-plan M8). First versioned, licensed preview of the project;
earlier `v0.1.0-alpha.1` / `v0.2.0-alpha.1` tags existed only as checkpoints with no license, no
consistent version string, and no release notes.

This is a **0.x developer preview**, not a 1.0: the scope and the performance gate below are
narrower than the project's original target, by owner decision (`docs/RELEASE-PLAN.md`,
"Decided 2026-10-10"). See `docs/release-policy.md` for the versioning scheme and the
SONAME/ABI statement this release establishes.

## What's in

**Licensing (M1).** MIT for the framework, the transpiler, and the D bindings
(`solid-qml-d`); LGPL-3.0-only for the C++ CSS engine (`vendor/qml-css-engine`), which contains
code derived from Qt (a literal port of `QQuickText`'s layout in `csstextlayout`) — a `NOTICE`
file documents that provenance. The GitHub repo was previously public with no license at all.

**Naming and versioning (M8, this release).** One version everywhere (`0.3.0-preview.1`),
checked by `scripts/check-version-consistency.mjs` (wired into `meson test` and `npm test`).
Public name **solid-qml** in docs/README/package.json (the engine and the D bindings keep their
own repo names). `libsolidqml`'s SONAME/ABI policy for 0.x is now explicit — see
`docs/release-policy.md`.

**Native widget port.** Every widget (HTML-derived — `<button>`, `<details>`, `<dialog>`,
tables… — and desktop-native — `<TabBar>`, `<SplitView>`, `<TreeView>`, `<ListView>`,
`<TableView>`, `<Menu>`, `<Tray>`…) is now a C++-backed type registered into the
`solidqml.Widgets` module (ported from hand-written `.qml`, for AOT-friendliness); the
transpiler instantiates them instead of emitting their internals by hand.

**`<RichText>` / `<DocumentEditor>`.** A word-processor-grade rich text editor: named
paragraph/character styles, numbered lists, indent/outdent, page breaks, incremental outline and
word/character counts, cut/copy/paste with `canPaste`, inline images and tables, and a full
**OpenDocument (ODF) round-trip** — written through our own ODF writer, read through our own
`content.xml` parser (not a reimplementation of LibreOffice's, a from-scratch one scoped to what
the editor itself produces and the common subset other writers emit).

**Keyboard & accessibility for plain elements (M5).** `tabIndex`/`role`/`aria-*` on a plain
`<div>`/`<text>` now map to real QtQuick facilities (`activeFocusOnTab`, the `Accessible`
attached type) with Enter/Space activation — previously a no-op with a console warning.
Accessible name now falls back to visible content when no `aria-label` is given.

**`<For>` row identity (C23).** Decided: reference identity by default (matches Solid-on-web —
a new object with the same `id` is a new row), `key="field"` opts into reuse-by-id. Implemented
in the engine (`CssRepeater.key`) and the transpiler (`<For key>`); covered by the engine's
repeater suite and the app-level `for-identity` / `for-identity-virtual` tests.

**Install story from a clean machine (M6).** The submodule URL is HTTPS (was SSH, which fails
for anyone without the owner's push access). `docs/getting-started.md` has a verified dependency
list (including the Qt *private* headers this library needs — most distros don't split those
into a separate package the way Arch doesn't split them at all). A new app
(`tests/clean-room/hello-app`) builds and runs **outside** this checkout, against the *installed*
`solid-qml-loader`, verified end-to-end in a from-scratch `archlinux:latest` container
(`scripts/clean-room-check.sh`; evidence in `docs/evidence/m6-clean-room-counter.png`).

**Transpiler correctness fixes.** Several silent-miscompile fixes landed this cycle: `const`/
`let` classification (seeding from every eager-binding position, not just the first; freezing
render-local identifiers that close over inter-candidate references), `createEffect` dependency
tracking (props/stores/context/`QObject` properties; a component's own plain values are never
spurious dependencies), module-level helper functions emitted into every component that uses
them, and `<For>`'s index accessor mapped correctly to the delegate's second parameter. `<Menu>`/
`<ContextMenu>` now accept `<For>`/`<Show>` for dynamic items.

## Known limits

- **The performance gate is narrower than the project's original target.** Measured
  ([docs/performance.md](../performance.md), methodology and raw data in `bench/results/`): in our
  1,000-row scrolling-list benchmark the automatically virtualized native list beats the same Solid
  app in headless Chromium on all six js-framework-benchmark operations (4–15× on synchronous time,
  also faster to the next presented frame) — because only the visible rows are materialized.
  Non-scrolling (eager) lists are **2.6× slower** to create/append at 1,000 rows and slower on all
  six operations at 10,000; a materialized row costs ~21 KB PSS vs ~11 KB in Chromium's renderer;
  "update every 10th" without `key` is slower than the web on eager lists. No GPU presentation and
  no Electron comparison were measured.
- **The AOT (C++) code-generation back-end is experimental, not a production path.** The shipped
  runtime path is TSX → QML + the C++ CSS engine + widgets + loader/embed library.
- **One supported environment.** Linux x86_64, Qt 6.11.2 pinned, verified on Arch/Manjaro
  (including a from-scratch `archlinux:latest` container) and manually on Wayland and X11.
  Debian/Ubuntu/Fedora package names in `docs/getting-started.md` are a best-effort mapping,
  **untested**. No Windows, macOS, Android, iOS, or npm/AppImage/SDK distribution channel yet —
  source only (git clone + submodule), see `docs/release-policy.md` for what a release contains.
- **No ABI stability in 0.x.** `libsolidqml` links against Qt's private headers; it is built for
  exactly one Qt minor (6.11) and must be rebuilt on any Qt or solid-qml upgrade. Full statement
  in `docs/release-policy.md`.
- **`<Menu>` theming limits and other known widget issues** are tracked, not hidden; the current
  list, with workarounds, is `docs/known-issues.md` (e.g. `<WebView>` going black after hide/show).
  What is supported at all is `docs/support-matrix.md`, including a few constructs that compile
  without an error but are wrong at runtime.
- **Core behaviour validated on a real display is still partial** (release-plan M4): popups/GPU
  paths cannot be validated offscreen; some menu-positioning behaviour still waits on a live-display
  session.

## Supported environment

- Linux x86_64, Qt **6.11.2** (pinned — private-header dependency, see above).
- Distro: Arch/Manjaro, verified; a from-scratch `archlinux:latest` container build is part of
  the test gate (`scripts/clean-room-check.sh`).
- Display: Wayland and X11, both exercised manually; most of the automated test suite runs
  `QT_QPA_PLATFORM=offscreen` (cannot validate GPU/popup behaviour — see "Known limits").
- Node 26 tested for the transpiler/toolchain; `vite@7` requires Node `^20.19 || >=22.12`.
